# OkRouter 测试说明

运行时模块使用 JUnit 4 与 Robolectric。当前单元测试位于 `okrouter/src/test`，覆盖请求构造、URI 规则、响应约束、仓储匹配，以及 V1 执行模型。

## 运行测试

```bash
./gradlew :okrouter:test
./gradlew :demo-app:assembleDebug
```

第一条会执行 Debug / Release 单元测试；第二条验证应用模块可完成插件生成与打包。首次在新 worktree 运行时，需要复制或配置本机 Android SDK 的 `local.properties`。

## 用例分布

| 测试文件 | 主要覆盖 |
|---|---|
| `RouterRequestTest` | Builder 的空 URI 校验、query 解析、extras / headers 复制、`start` 的非法请求处理。 |
| `RouterResponseTest` | Response Builder 必填字段、`Ok + UNDEFINED` 禁止组合、结果载荷与复制。 |
| `RouterUriTest` | 稳定/正则 URI 判断、优先级比较与字符串格式。 |
| `WareHouseTest` | 稳定/正则匹配、去 query/fragment 的动态缓存键、重复注册、确定性排序、拦截器优先级与单例并发。 |
| `RouterExecutionModelTest` | `resolve` 无副作用与不可变快照、新旧 Handler/拦截器混排、旧响应保真、重定向、循环、观察者隔离、Builder 与静态入口兼容。 |

## 已验证的关键边界

- 公开 `resolve` 匹配正则路由时不写 `dynamicRouters`；真实 `start` 会写缓存。
- `RouterMatch.Found.parameters` 是不可变快照，改变原 `RouterRequest.extras` 不会回写解析结果。
- 旧六参数 `RouterMeta` JVM 构造函数仍存在，旧生成 Loader 可继续链接。
- 旧 Handler / 拦截器、V2 Handler / 拦截器可以混排；旧 `RouterResponse` 的结果、headers、target 不丢失。
- 旧拦截器 `proceed()` 下游返回 V2 Redirect 时，Redirect 会由 Dispatcher 处理。
- 第 8 次重定向可成功，第 9 次失败；改变 query/fragment 的同路径循环也会失败。
- Redirect 保留 headers、extras、requestCode、routerType、launcher；URI query 只补充缺失 extras。
- 观察者或日志器抛异常不会改变响应，也不会阻止后续观察者。

## 使用测试理解行为

测试不是 API 合同的唯一来源，但它们是当前版本最精确的边界证据。排查行为时建议按以下顺序阅读：

1. 从 [API 参考](API参考.md) 确认公开约定。
2. 从 `RouterExecutionModelTest` 查找同类结果或异常边界。
3. 从 [架构说明](架构说明.md) 判断该行为发生在生成期、匹配期还是执行期。

当前测试主要验证运行时与 Demo 构建；对插件生成源码的细粒度快照测试较少。修改生成器时应额外执行 `:demo-app:assembleDebug` 并检查生成的 Loader 与路由文档。
