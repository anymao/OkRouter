# 如何使用 OkRouter

本手册面向已完成基础接入的使用者。API 的完整签名请查看 [API 参考](API参考.md)。

## 如何向目标传参并接收 Activity 结果

```kotlin
val response = OkRouter.build("okrouter://android/order?tab=detail")
    .putLong("orderId", 1001L)
    .header("trace-id", traceId)
    .launcher(orderLauncher)
    .start(this)
```

- `launcher` 优先于已废弃的 `requestCode`；两者都不存在时，普通 Activity 跳转使用 `startActivity`。
- `requestCode` 仅在 `Context` 是 `Activity` 且值大于 0 时生效。
- query 参数会进入 extras；同名显式 `put*` 值在首次 `build()` 时会被 URI query 覆盖。重定向时则相反，原 extras 优先，目标 URI query 只补充缺失键。

## 如何获取 `View` 或 `Fragment`

目标是 `VIEW` 或 `FRAGMENT` 时，实例会放入 `RouterResponse.target`。

```kotlin
val response = OkRouter.build("okrouter://android/custom_text_view").start(this)
val view = response.getView() ?: return
container.addView(view)
```

`getView()` / `getFragment()` 会检查 `routerType`；不匹配时返回 `null` 并记录警告。`requireView()` 在没有 View 时抛出异常。当前 `requireFragment()` 是历史兼容 API，返回类型错误地写成 `View`，请使用 `getFragment()` 并自行判空。

## 如何实现旧版 Handler 或拦截器

旧接口继续受支持，适合已存在的业务模块。

```kotlin
@Router(scheme = "okrouter", host = "android", path = "/refresh")
class RefreshHandler : RouterHandler {
    override fun handle(context: Context, request: RouterRequest) {
        val force = request.getBooleanCompatibly("force")
        refresh(force)
    }
}

@Interceptor(alias = "login", priority = Int.MIN_VALUE, singleton = true)
class LoginInterceptor : RouterInterceptor {
    override fun intercept(context: Context, chain: RouterInterceptor.Chain): RouterResponse {
        return if (signedIn()) chain.proceed(context, chain.request())
        else interceptRequest(chain.request())
    }
}
```

`RouterInterceptor.Companion.interceptRequest(request)` 会生成 `RouterResult.Intercepted`。全局拦截器和路由局部拦截器合并后按 `priority` 从小到大执行；同优先级按类名保证确定顺序。

## 如何使用 V2 Handler、V2 拦截器和重定向

V2 API 使用 `RouterOutcome` 表达完成、拦截、失败或重定向。旧接口与 V2 接口可以混排。

```kotlin
class LoginGate : RouterHandlerV2 {
    override fun handle(context: RouterContext): RouterOutcome =
        if (signedIn()) RouterOutcome.Completed()
        else RouterOutcome.Redirect("okrouter://android/login?from=gate")
}

class AuditInterceptor : RouterInterceptorV2 {
    override fun intercept(chain: RouterChain): RouterOutcome {
        audit(chain.context.request.uri)
        return chain.proceed()
    }
}
```

重定向行为：

- 最多允许 8 次实际重定向；第 9 次返回 `RouterResult.Failed`。
- 循环按去除 query 和 fragment 后的 URI 检测。
- 响应 `uri` 保持首次 URI；`Extend.OKROUTER_FINAL_URI` header 保存最终执行 URI。
- 原请求的 headers、extras、requestCode、routerType 和 launcher 会保留。
- 重定向 URI query 仅补充缺失 extras；与已有 extras 同名时保留原 extras。

## 如何处理未找到的路由

```kotlin
OkRouter.routerLostHandler = object : RouterLostHandler {
    override fun handle(context: Context, request: RouterRequest) {
        reportMissing(request.uri)
        OkRouter.build("okrouter://android/404")
            .putString("lostUri", request.uri)
            .start(context)
    }
}
```

原请求仍会得到 `RouterResult.NotFound`。`RouterLostHandler` 适合埋点或主动跳转到兜底页；不要把它当作 `resolve` 的回调，`resolve` 完全不会调用它。

## 如何记录路由观测事件

```kotlin
val observer = object : RouterObserver {
    override fun onResolved(match: RouterMatch) {
        analytics.routeResolved(match)
    }

    override fun onFinished(context: RouterContext?, outcome: RouterOutcome) {
        analytics.routeFinished(context?.request?.uri, outcome)
    }
}

OkRouter.addObserver(observer)
// 不再需要时：
OkRouter.removeObserver(observer)
```

观察者和日志器发生异常都会被隔离，不会中断路由或阻止其他观察者。不要在观察者中改变请求或把它作为业务鉴权的唯一位置。

## 如何排查常见问题

| 现象 | 检查项 |
|---|---|
| `OkRouter 未初始化` | 在 `Application.onCreate` 调用 `OkRouter.init(this)`，或显式传入 `start(context)`。 |
| `NotFound` | 检查应用模块是否启用了插件、路由注解是否在构建 classpath 内、scheme/host/path 是否匹配。 |
| 正则路由命中不符合预期 | 为更具体的规则设置更小的 `priority`；同优先级按规则字符串排序。 |
| 拦截器没有运行 | 检查 `@Interceptor(global = true)`，或是否已在 `@Router.interceptors` / `interceptorsByAlias` 声明。 |
| Handler 实例化失败 | Handler 需要无参构造；V2 Handler 仍必须继承 `RouterHandlerV2`。 |
