# Proposal: AGP 8.13.0 适配

## 背景

OkRouter 项目目前使用 Android Gradle Plugin (AGP) 7.4.0，配合 Gradle 7.5 和 Kotlin 1.8.0。随着 AGP 8.x 的普及，项目需要升级以支持最新的开发环境和工具链。

### 当前状态

| 组件 | 版本 | 状态 |
|------|------|------|
| AGP | 7.4.0 | 旧版本，长期支持将结束 |
| Gradle | 7.5 | 不匹配 AGP 8.x 的要求 |
| Kotlin | 1.8.0 | 不匹配 AGP 8.x 的推荐版本 |
| JDK | 17 | ✅ 已满足要求 |

### 挟战

AGP 8.x 正式弃用了 `Transform API`，这是 OkRouter 插件当前使用的核心 API。需要找到合适的迁移路径。

## 目标

将 OkRouter 项目适配到 AGP 8.13.0，确保：

1. ✅ 构建系统兼容 AGP 8.13.0
2. ✅ 插件功能完全保持不变
3. ✅ 支持增量编译
4. ✅ 最小化代码变更，复用现有逻辑

## 约束条件

- **版本锁定**：采用 AGP 8.13.0 + Gradle 8.13 + Kotlin 2.1.0（已验证的稳定组合）
- **向后兼容**：保持现有的路由注解和 API 不变
- **性能要求**：迁移后性能不低于原实现
- **测试覆盖**：示例应用必须正常运行

## 范围

### 包含

- ✅ 升级 AGP 到 8.13.0
- ✅ 升级 Gradle 到 8.13
- ✅ 升级 Kotlin 到 2.1.0
- ✅ 重构插件从 Transform API 到任务依赖管理
- ✅ 验证所有模块的 namespace 配置
- ✅ 完整的测试和验证

### 不包含

- ❌ 路由功能特性的新增或修改
- ❌ 示例应用的业务逻辑变更
- ❌ 文档国际化

## 关键决策

### 技术方案选择

**选择：任务依赖管理方式**

**理由**：
1. auto-service-android 已成功使用此方案适配 AGP 8.13.0
2. 避免使用复杂的 AsmClassVisitorFactory API
3. 完全复用现有的扫描和生成逻辑（`AbsOkRouterAction`）
4. 迁移工作量和风险显著降低

### 版本选择

**AGP 8.13.0 + Gradle 8.13 + Kotlin 2.1.0**

**理由**：
1. auto-service-android 已验证此组合的稳定性
2. AGP 8.13.0 是经过充分测试的稳定版本
3. 匹配的 Gradle 和 Kotlin 版本确保兼容性
